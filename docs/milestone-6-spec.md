# Milestone 6 — Marks and evidence: the Reference type

PRD §14 lists a Mark's optional evidence as "an artifact (URL, image, document,
Reference)" and the data-model section (§9-ish list) gives Reference its own
entry: "label, URL, attached entity." What's actually built (through
milestone 5) is a single free-text `artifact` string on `mark.recorded` —
whatever the user typed, unlabelled, un-typed. This milestone closes that gap
for the one place Reference is actually used in v1: as a Mark's optional
evidence.

## §0. Scope decision

Two ways to read the PRD's separate "Reference" data-model entry: a real
direction table (own id, reusable, attachable to future entity kinds via a
pointer), or a structured field living inside the Mark event itself. Decided
with the user: **structured field on Mark** — `payload.reference = { label,
url }` instead of `payload.artifact = string`. No new table. Same trust level
as everything else in a Mark's payload (an event field, not a foreign-keyed
row) — consistent with how Undertakings/Probes/Outcomes statements live
directly on `quests`, not a separate statements table. If a future milestone
needs a Reference attached to something other than a Mark, promoting it to a
real table is a migration away; nothing here forecloses that.

## §1. Shape

```
payload.reference = { label: string, url: string }
```

Both fields required together — a reference with a URL but no label is just
the old bare-string problem again (what is this a link *to*?), and a label
with no URL isn't evidence, it's a second note. `artifact` (the old bare
string field) is retired: no new Marks write it, and nothing reads it going
forward. Existing rows that already carry the old shape are untouched (the
event log is append-only) but simply won't display a reference — there's no
backfill, since there were only ever a handful of real Marks and none of
them used `artifact` for anything worth preserving as a fake label.

## §2. Validation

`db/migrations/0011_mark_reference.sql` adds `events_valid_mark_reference`,
mirroring `events_mark_has_note`'s pattern (0006): for `mark.recorded` /
`mark.recorded.corrected`, if `payload` has a `reference` key, it must be a
JSON object containing both non-empty `label` and non-empty `url`. Absence of
`reference` entirely is fine (a Completed, undocumented Mark) — the
constraint only fires once a `reference` key exists at all.

## §3. Mark state (PRD §14)

"Mark states: Completed (note only) · Documented (note + artifact)." Read,
not stored — `RecentMark.state` is computed as `reference ? "documented" :
"completed"` at query time, the same way every other derived label in this
app (rank, momentum) is computed from the log rather than cached. *Verified*
(the third state) stays unimplemented, per the PRD's own "reserved... not
implemented in v1."

## §4. Call sites

Every path that can produce a `mark.recorded` event gets the same two-field
(Label / URL) form in place of the old single Artifact field:

- `app/(loop)/marks/page.tsx` — ordinary Mark creation and edit
- `app/audit/page.tsx` — the audit wizard's retroactive Marks
- `app/(loop)/quests/page.tsx` — the optional Mark generated by completing an
  Undertaking or achieving an Outcome (`lib/quests.ts`'s `completeUndertaking`
  / `achieveOutcome`, which both delegate to `recordMark`)

`lib/marks.ts`'s `RecordMarkInput`, `RecordRetroactiveMarkInput`, and
`EditMarkInput` all take `reference?: { label: string; url: string }` in
place of `artifact?: string`. `lib/quests.ts`'s `AchieveOutcomeInput` and
`CompleteUndertakingInput` follow the same rename, since both just forward
into `recordMark`.

## §5. Display

Where a Mark's artifact used to render as plain text, it now renders as a
link (`<a href={reference.url}>{reference.label}</a>`) when present. The
domain/date line gains the Completed/Documented state alongside the existing
domain and logical-day text.

## §6. Definition of done

- Migration applied; constraint rejects a `reference` with only one of
  label/url, or either one empty.
- `recordMark` / `recordRetroactiveMark` / `editMark` accept and store
  `reference`; `listRecentMarks` returns it plus the computed `state`.
- All three UI call sites (Marks, Audit, Quests) offer Label + URL instead of
  a single Artifact field, and the Marks list renders the reference as a
  link and shows Completed/Documented.
- `npm test` green against the real dev database, including new coverage for
  the reference validation and the Completed/Documented state.
